Kubernetes ensures: “Your app is ALWAYS running, ALWAYS reachable, ALWAYS scalable”

Even if: servers crash, traffic spikes, deployments fail

Node (Machine) are of two type 
· Control Plane (brain)
· Worker Node (does actual work)

Pod (Smallest unit) 👉 A Pod = one or more containers running together
💡 Important: You NEVER deploy containers directly Kubernetes wraps them inside Pods

Deployment (Auto manager)
👉 You never run Pods manually in production.

Deployment says:
“I want 3 replicas of my app ALWAYS running”

Kubernetes ensures:
If 1 Pod dies → new one created
If Node crashes → rescheduled somewhere else

Service (Networking layer)

Pods are: dynamic they die & recreate, IP changes

👉 So Service gives:
stable IP
load balancing

Scheduler (Brain decision maker)

👉 Decides: “Which Pod goes to which Node?”

Based on: CPU Memory rules affinity

Kubelet (Node agent)

👉 Runs on every node
Responsible for: creating pods talking to control plane
